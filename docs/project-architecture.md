# 项目组织约定

2026-09-13 确认。求解器内部架构已经确定，本约定组织实验、计算记录和分析产物。

## 目录与职责

```text
solver/                              已确定的数值实现
experiments/<experiment>/
  README.md                          研究目的、控制变量、观测量、执行说明
  configs/                           计算、批次和分析的可编辑配置，按需创建
  run.py                             显式执行计算
  analyze.py                         加载指定结果并分析
  explore.ipynb                      可选：探索、交互分析、调整图表
runs/<experiment>/<run-id>/           一次计算尝试的配置、状态、数据、日志
runs/<experiment>/batches/<batch-id>/  批次配置与成员运行清单
reports/<analysis-name>/<analysis-id>/
  analysis.json                      输入运行、分析参数、分析源码信息、状态
  figures/                           生成的图
  tables/                            生成的表和统计汇总
  analysis.log                       本次分析日志
docs/                                项目约定、实验盘点与迁移记录
tools/                               仓库维护工具
archive/                             历史索引及确认停用的代码
tests/                               数值与工作流检查
```

目录按实际需要建立，不为每个概念单独拆文件。小实验可在一个脚本内用函数区分职责。2026-09-24 迁移后，各实验默认配置统一位于 configs；旧配置与入口一起归档。

实验按研究问题组织，如收敛性、回归参数影响、长时间统计、空间分辨率。同一实验中的不同数值格式和步长方式由配置选择，不按格式复制整个实验。跨实验分析的代码放在一个有明确比较目的的 `experiments/<比较主题>/` 中，生成结果仍进入 `reports/`。

## 计算、批次、分析三种记录

**计算运行**：一套实际生效的参数调用一次求解流程。运行身份包含相关数值参数、源码和环境；运行编号标识一次尝试。同身份显式重跑也创建新编号。成功复用须检查兼容性和完整性；失败/未完成不得当作成功。保留现有运行记录协议，不在本轮统一不同历史格式。

**批次**：一份扫描配置展开为若干算例，每个算例有稳定 case-id、完整参数和所选 run-id。批次目录保存 `config.json`、`manifest.json`、`batch.log`；清单记录 pending/running/completed/failed 及是否复用。一个算例失败不抹去其他算例。重试只对显式选中的失败项新建运行尝试，并保留之前的运行编号。相同兼容参数可在多个批次中引用同一已完成运行。

**分析**：明确指定输入的 experiment、run-id、结果位置及需要的身份信息；也可读取批次清单，但开始分析时必须将成员解析成固定运行列表写入 `analysis.json`。保存实际分析参数、相关分析源码哈希、环境和输出清单。默认创建新分析编号，图表全部保存成功后标记 completed。改颜色、标签或统计窗口只执行分析；缺失/不兼容输入报错，不启动求解，不自动选择最新运行。

跨运行图表属于分析记录，不能挂在其中某一个输入运行下面。已有运行中的预留 figures/tables 目录可保留，后续新分析统一写入 reports。新分析记录不会修改输入运行及其日志。

分析遇到失败输入时，默认明确报错；专门研究失稳的分析可显式允许失败数据，但必须展示状态、实际终止时间和有效区间。未解析历史数据来源前，使用明确的 legacy 路径引用并标注 unknown，不伪造 run-id、源码版本或完成状态。

## Notebook 与公共代码

正式计算由脚本执行。Notebook 默认读取明确选择的数据，服务交互分析和图表调整。探索阶段允许直接计算；成熟后提取正式脚本、集中配置和保存协议。调整图表不能依赖先执行昂贵计算单元才能得到的隐式状态。

共享代码只在实际复用时提取：优先考虑运行记录、配置读写、结果加载和绘图样式。初值、物理诊断和分析公式先留在具体实验。第二个实验需要同一实现时，再放入少量 `experiments/common/` 模块；暂不创建注册系统、插件机制或通用实验基类。

## 历史产物与 Git

历史 data/fig/figures/logs/output/tmp 原位保留，通过索引登记路径和来源证据。文件名只能作为线索；完整参数、计算状态和来源需另行核验。修改时间不是计算时间。同编号或带 `2` 的 notebook 不据此合并或删除。

源码、配置、文档和轻量索引纳入 Git。runs 和 reports 是可追溯的本地产物，默认忽略；Git 忽略不等于备份，长期数据仍需按实际存储条件另行备份。用于论文的正式图表可以显式导出到论文仓库，并附输入运行和分析编号；不为此取消全局图片忽略规则。

历史索引使用 `python tools/index_legacy_artifacts.py` 更新。它只读取目录和 stat 元数据，既不读取大数组，也不推断数值参数。索引不是实时目录视图或完整性校验。归属与迁移进展见 [实验清单](experiment-inventory.md)。

## 迁移边界与完成标准

先盘点并核对归属，再逐个迁移活跃实验。建议顺序为 bursting 的独立分析、已有 transition 比较、收敛性与变步长实验，其余依研究需要排期。用途未确定的 notebook 暂留。

一个实验迁移完成须具备：集中且有说明的配置；正式计算脚本；独立分析入口；明确输入/输出记录；小规模保存、加载、重复分析不计算的检查；旧/新数值结果的适当对照。更新导航并记录旧入口去向后，才归档确认停用的入口。
